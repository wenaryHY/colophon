# 枚举、Radix 与自动 HTTPS——InkForge 技术债清算记

写代码最爽的时刻，不是加新功能，是删代码。六月这一轮，我们删了快四百行。不是砍功能，是把当初为了赶进度写的妥协方案，一件件还回去。这篇文章记录这几周做的事情——不算 feature，但比 feature 更重要。

## 字符串地狱的终结

InkForge 的数据模型里，`PostStatus`、`Visibility`、`ContentType` 这三个字段，从立项那天起就是字符串。`"draft"`、`"public"`——写着方便，IDE 也能补全，甚至觉得自己挺灵活。直到某天，有人把 `"publc"` 写进了数据库，一个 typo 埋了两周才被发现。

改。全部改成 Rust 枚举。

```rust
pub enum PostStatus { Draft, Published, Archived }
pub enum Visibility { Public, Private, PasswordProtected }
pub enum ContentType { Markdown, Richtext, Html }
```

然后？编译器接管了一切。每个 `match` 必须穷尽分支，序列化/反序列化自动生成，连数据库 migration 都能推导。重构涉及十几个文件，改完跑测试——**199 个测试全部绿灯**。一个字没改逻辑，只是换了类型系统，感觉就像把一团纠缠的耳机线解开，插上蓝牙。

## 八臂 match 的消失

重构枚举的时候，翻到一个函数里有 8 个分支的 `match`，每个分支做的事情差不多——构建 SQL 查询。不同状态拼不同 `WHERE` 子句，不同可见性拼不同参数，八条分支互相交叉，读起来像在看星形拓扑图。

直觉告诉我这不对。翻了翻 sqlx 文档，发现 `QueryBuilder` 正好是干这个的：动态追加查询条件，不用预设所有分支。改完之后，函数从一百多行缩到二十行，逻辑变成了一串 `.push_bind()`，线性、可读、扩展只要加一行。**净减 182 行**——包括删掉的注释和空行。

这才是删代码的快感：不是偷懒，是找到了正确的抽象。

## 十六参数的函数？不，是 struct

清理过程中遇到一个函数签名占了整整三行编辑器宽度：16 个参数，类型从 `&str` 到 `Option<NaiveDateTime>` 都有。传参的时候每行对齐三个，还容易搞错顺序。

这类问题不需要什么高级设计模式。把所有参数装进一个 struct，函数签名叫 `handle(ctx, args)`，函数体里 `args.title` 不比第八个位置参数清晰多了？一行改动，零风险重构。这种"低垂的果实"在技术债清算时最值得摘——改起来爽，风险又低。

## 类型系统的面子

还有一个 `i64` 字段，实际只有 0 和 1 两个值，存的是"是否置顶"。当时大概是图方便，直接用了数据库整型。现在给它平反——改成 `bool`，SQLx 自动映射到 `BOOLEAN`，migration 一条 `ALTER`，语义终于和类型一致了。

这种小修小补单独列出来显得小题大做，但技术债不就是这些小事堆积起来的吗？一处 `i64` 当 bool 用不可怕，可怕的是新来的人看到这个用法，以为这是惯例。

## 评论限流：从 Redis 回到内存

InkForge 的评论限流最初跑在内存里，后来为了"可扩展"加上了 Redis。结果 Redis 挂了两次——一次端口冲突，一次容器重启没持久化——每次用户端都直接绕过限流。可笑的是，当前只有一台服务器。

去掉 Redis 依赖，用 `tokio::sync::RwLock<HashMap<IpAddr, Vec<Instant>>>` 实现滑动窗口限流，不到 40 行。少了依赖、少了故障点、少了运维负担。如果需要分布式的那天真的到来，再加回去也不迟。过早优化不一定是万恶之源，但过早分布化一定是。

## Radix UI 接管 Select 组件

前端的 Select 组件是自己写的，452 行，涵盖了键盘导航、焦点管理、选项过滤、多选逻辑——看起来挺厉害。实际上，每两周就有人报一个边缘情况的 bug：空格键行为不一致、移动端选项面板飞出屏幕、下拉菜单被父容器裁剪。

这些交互细节，Radix UI 的团队已经打磨了无数遍。换上去不到 50 行：

```tsx
<Select.Root>
  <Select.Trigger />
  <Select.Content>
    {items.map(i => <Select.Item value={i}>{i}</Select.Item>)}
  </Select.Content>
</Select.Root>
```

组件样式自己控，行为逻辑交给 Radix。452 行删到 50 行，还修了三个陈年键盘导航 bug——用别人的轮子不丢人，尤其是比自己造的好用得多的时候。

## ACME 自托管 HTTPS 的探索

InkForge 一直假设用户会套一层 Nginx 处理 HTTPS。但这对于一个"开箱即用"的无头 CMS 来说，准入成本太高了。六月花了不少时间调研自托管 HTTPS 的方案。

结论是用 `rustls-acme` + `axum-server`，在应用层直接处理 TLS 终止和证书自动续期：

- `rustls-acme` 负责 ACME 协议交互（对接 Let's Encrypt 或 ZeroSSL）
- `axum-server` 原生支持 `rustls`，省去中间层
- HTTP-01 challenge 走内置的 well-known 路由，DNS-01 预留接口

写了一个概念验证，从启动到拿到第一张证书不到十秒。这个功能还没合入主线，但方向已经清楚了：一个二进制文件，启动即 HTTPS，零外部依赖。

## 711 crates + 85 npm 包的合规审计

这是六月最枯燥但也最让人安心的工作。跑了一遍 `cargo-deny` 和 `license-checker`，逐个确认 711 个 Rust crate 和 85 个 npm 包的许可证。结论：**全部可商用**，没有 GPL 炸弹，没有未授权许可证，供应链暂时清白。

这件事的价值不在当下——现在没人查你。但如果 InkForge 有一天要进企业市场，许可证审计就是准入门票。趁现在依赖树还小，先做完。

---

这一轮做的事情都不性感。没有新 UI、没有 AI 功能、没有任何可以截屏发推特的时刻。但一行一行删掉自己当初草率写下的代码，把"先这样吧"变成"就该这样"，是另一种满足感。技术债不会自己消失，它只会在你加新功能的时候悄悄涨利息。六月，我们连本带利还了一笔。

现在，代码库里少了三百多行，多了六个枚举，少了一个 Redis 容器，多了一张绿色测试墙。

可以安心写下一个 feature 了。
