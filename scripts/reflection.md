# 从零到上线：一个 Rust CMS 的诞生记

五月初，InkForge v1.0 上线了。一个用 Rust 写的博客 CMS，一个人，从零到部署上线，正好一个月。

回头看看，有些话想说。

## 一个人写完整 CMS 是什么体验

诚实地说，累，但爽。累是因为所有决策都要你自己做，没人帮你挡。爽也是因为所有决策都是你自己做，没人拦你。

技术栈自己定：Axum + SQLite + React + Tiptap。没有微服务的拆分焦虑，没有技术选型的政治斗争。觉得 SQLite 够用就直接用，不需要写一份说服别人的文档。觉得 MiniJinja 比 Askama 更适合主题系统就换，不用经过邮件审批。

但这也意味着你是唯一背锅的人。凌晨三点发现线上评论系统不推送了，只有你爬起来看日志。WebSocket 断连、模板渲染出错、文件上传失败——每一个报错都是你的。

这种"全部的责任感"跟上班写代码完全不同。上班时一个 bug 最多影响组内的迭代节奏。自己上线的东西出了问题，就是你对着一个访问不了的网站干瞪眼。

## 部署到 DigitalOcean + Cloudflare

服务器是 DigitalOcean 1 核 2G 的机器，一百多块一个月。前面挂 Cloudflare 做 CDN 和 DNS，顺便白嫖免费的 SSL。

部署过程比想象中顺利。Rust 编译出来的单个二进制文件大概 11MB，`scp` 传上去，配个 systemd 服务就跑起来了。Nginx 反代几行配置，Cloudflare 改个 DNS 记录，半小时搞定。

真正花时间的是安全加固。单独建了 `inkforge` 系统用户，生产密钥不写进 systemd unit，应用只绑定 `127.0.0.1:2000`。还把后端的安全审计工具都跑了一遍——nuclei 扫 HTTP 漏洞，sqlmap 测 SQL 注入，XSStrike 打 XSS。每一轮扫完都心惊胆战，生怕自己的 API 被一把梭穿。

还好，没出大问题。唯一一次核弹级发现是 nuclei 扫出来一个路径穿越嫌疑——主题 ZIP 上传时如果解压不校验路径，可以读到系统文件。好在 Rust 的 `fs_extra` 的 `enclosed_name()` 已经挡掉了这发子弹，虚惊一场。

## 上线之后的"运维焦虑"

代码写完了，真正的心跳加速才刚开始。

把二进制推到服务器上，`systemctl start inkforge`，然后你对着浏览器刷新。那一刻的紧张感跟等高考成绩差不多。出问题了吗？端口对吗？防火墙开了吗？为什么 Cloudflare 报 521？Nginx 的 `proxy_pass` 写对了吗？

说实话我从来没管过服务器。systemd 的 unit 文件是现学的，Nginx 的 `proxy_set_header` 是从 Stack Overflow 复制过来一个个试的。我第一次配好以后访问 `https://wenary.me` 看到自己的博客出来——那个感觉比写完任何一行代码都爽。

但这只是开始。后来我把应用从 root 用户改成了独立的 `inkforge` 用户，加了 `ProtectSystem=strict`、`NoNewPrivileges`、`PrivateTmp`，把应用目录锁成只读。做这些的时候我一直在想：我现在做的这些，是不是运维每天都在做？他们真不容易。

## 用黑客工具攻击自己的网站

上线后的第二天，我做了一件可能有点疯的事情：把自己当成攻击者，用安全工具打自己的服务器。

在 WSL 里装了 hackingtool，把 nuclei（6220 个漏洞模板）、sqlmap（SQL 注入）、XSStrike（XSS）、TruffleHog（密钥扫描）、testssl.sh（TLS 深度检测）全跑了一遍。每跑一轮都手心出汗——万一扫出来个 SQL 注入呢？万一我的 API 能被未认证访问呢？

还好，除了一个误报（nuclei 把 `/api/v1/version` 误判成 Langflow 的 CVE），没有任何真实漏洞。那一刻我才真正相信自己的代码不是筛子。

但安全审计教给我一件事：你不能只靠"我觉得安全"。你必须用工具验证。你写的那行 `if user.role != "admin"` 是不是真的在所有路径上都生效了？你没写测试的路径，攻击者会帮你测。

## 和 AI agent 协作的真实感受

这一个月里，AI agent 不是"帮我写代码"，而是"帮我少走弯路"。

它最擅长的不是生成代码，是排查方向。我描述一个问题，它能列出三四种可能的原因，我自己逐一验证。ammonia 那个坑的第三轮排查方向就是它提的："你确定实际调用的函数是你配置过的那个吗？"

另一个作用是帮我守住工程质量底线。它会主动提醒"这个函数超过 40 行了，要不要拆"、"这个硬编码的端口号应该提取成常量"。一个人写代码最怕的就是放飞自我，有个东西在旁边念紧箍咒，代码质量确实高了不少。

但 AI 不是银弹。它不熟悉我的项目上下文，给的建议有时候牛头不对马嘴。它不会真正"理解"你的架构意图，只能基于当前对话窗口做推断。跟它协作的诀窍是：把它当 code review 的助手，而不是写代码的主力。

## 重新认识"独立开发者"

以前觉得独立开发者就是一个人闷头写代码，写完上线，然后躺着收钱。

真实情况是：写代码只占三分之一。剩下的是测试、部署、安全审计、写文档、写发布文章、处理服务器运维。你把代码写完的那一刻，事情才刚刚开始。

还有一个心理层面的感受：孤独感是真实的。没有同事跟你讨论技术方案，没有产品经理告诉你"这个需求可以砍"，没有 QA 帮你测回归。所有事情都在你一个人的脑子里运转。有时候想找个人聊聊一个架构决策，发现对面没有人。

但当你打开浏览器，访问 `https://wenary.me`，看到自己一行行写出来的博客系统在完美运行——那个瞬间，值了。不是因为"做出来了"，而是因为"这是完全属于我的东西"。每一行代码都有自己的理由，每一个设计决策都经过了自己大脑的折腾。

如果有下一个人问我"要不要做独立项目"，我会说：做。但不是因为能做多大，而是因为你会成为更好的开发者。你会被迫面对所有你以前依赖别人处理的问题，而你发现自己其实可以。

> 写完这篇心得的时间是 2026 年 5 月 31 日，距项目启动正好一个月。感谢所有使用和关注 InkForge 的人。
